# پلتفرم نوبت‌دهی — Booking Platform

پلتفرم رزرو و نوبت‌دهی آنلاین با فرانت‌اند و بک‌اند مجزا، طراحی‌شده با تمرکز بر امنیت، صحت داده و مقیاس‌پذیری.

## وضعیت فعلی: فاز ۴ تکمیل شد — پرداخت و مالی

**فاز ۰** (پایه‌ریزی): schema کامل دیتابیس، مستندات معماری/API/design-system، اسکلت مانو-ریپو، Docker، CI.

**فاز ۱**: احراز هویت کامل (OTP، JWT+refresh rotation، مدیریت نشست، RBAC سراسری).

**فاز ۲**: ثبت کسب‌وکار، شعبه/خدمات/کارکنان، ساعات کاری، جستجوی عمومی، `BusinessRoleGuard`.

**فاز ۳**: موتور رزرو — availability، hold concurrency-safe (Redis+DB)، confirm/cancel/reschedule، رزرو تکرارشونده.

**فاز ۴** (این نسخه) — پرداخت و مالی:
- انتزاع درگاه پرداخت (`PaymentGateway` interface، دقیقاً مثل الگوی `SmsProvider`) — الان `MockPaymentGateway` که واقعاً verify می‌کنه (نه صرفاً true)، بعداً با زرین‌پال واقعی جایگزین میشه بدون تغییر `PaymentService`
- پرداخت بیعانه از دو مسیر: کیف پول (تراکنشی، آنی) یا درگاه (session + callback با verify سرور-به-سرور)
- Idempotency در callback: تراکنش پردازش‌شده دوباره پردازش نمیشه، حتی اگر گیت‌وی callback رو دوبار بفرسته
- کیف پول: شارژ، مشاهده‌ی موجودی و تاریخچه، برداشت اتمیک با تراکنش دیتابیس (جلوگیری از race روی موجودی)
- استرداد وجه توسط ادمین — همیشه به کیف پول کاربر (نه بازگشت مستقیم به کارت)، با audit log کامل شامل دلیل
- تسویه‌حساب دوره‌ای با محاسبه‌ی خودکار کمیسیون پلتفرم، برای یک یا همه‌ی کسب‌وکارهای تایید‌شده
- ۲۱ تست واحد جدید روی حساس‌ترین منطق کل پروژه (پرداخت، verify، replay، کمیسیون)

### دامنه‌ی خارج از این فاز (تصمیم آگاهانه، نه فراموشی)
لیست انتظار (waitlist) و رزرو گروهی چند-نفره پیاده نشدن — جزئیات و دلیل در `docs/api-contract.md`.

### حالت موقت OTP قبل از اتصال پیامک واقعی
تا وقتی یک provider واقعی پیامک (کاوه‌نگار و مشابه) وصل نشده، با `OTP_DEBUG_EXPOSE=true` در `.env`، کد OTP مستقیم در پاسخ API (فیلد `debugCode`) برمی‌گرده تا فرانت بتونه همون صفحه نشونش بده. این حالت **صرف‌نظر از مقدار env، در `NODE_ENV=production` همیشه غیرفعاله** — یک تنظیم فراموش‌شده نمی‌تونه در محیط واقعی کد رو لو بده. قبل از انتشار نهایی، باید هم این flag رو false کنید هم یک `SmsProvider` واقعی (پیاده‌سازی interface موجود در `common/sms/`) جایگزین `ConsoleSmsProvider` بشه.

منطق دامنه‌ی بعدی (رزرو، پرداخت) در فازهای ۳ به بعد اضافه می‌شه.

## راه‌اندازی محیط توسعه

```bash
# ۱. سرویس‌های زیرساختی (Postgres + Redis)
docker compose up -d

# ۲. نصب وابستگی‌ها (در ریشه‌ی مانو-ریپو)
npm install

# ۳. کپی فایل env
cp .env.example .env
# مقادیر واقعی (secrets) رو داخل .env جایگزین کنید — هرگز commit نشه

# ۴. اجرای migration اولیه
npm run prisma:migrate

# ۵. اجرای backend
npm run dev:backend

# ۶. اجرای frontend
npm run dev:frontend
```

## ساختار پروژه

```
/apps/backend    → NestJS API
/apps/frontend   → Next.js
/packages/shared → تایپ‌ها/enumهای مشترک
/prisma          → schema دیتابیس
/docs            → مستندات معماری و API
```
